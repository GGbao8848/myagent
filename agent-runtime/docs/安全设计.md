# AgentRuntime 安全设计

AgentRuntime 暴露「本机命令执行 + 文件读写」给远程 Agent，安全是核心。三层防护 + 审计，全在服务端强制，Agent 无法绕过。

## 防护总览

| 层 | 机制 | 拦截目标 |
|---|---|---|
| 1 | 只监听 localhost + MCP DNS-rebinding 防护 | 局域网/远程非法访问 |
| 2 | 目录白名单（realpath 校验） | 文件读写越界（`..`、符号链接、UNC 路径） |
| 3 | 命令白名单 + 参数级路径校验 | 任意命令执行、`python -c` 内嵌路径越权 |
| 4 | 审计日志（滚动落盘） | 事后追溯每次调用 |

## 目录白名单（path_policy.py）

- 配置项 `allowed_dirs`，支持多个；相对路径基于第一个允许目录解析
- **realpath 归一化后校验**：`..`、符号链接、`%VAR%`/`~` 展开后仍越界的一律拒绝（Windows 大小写不敏感）
- 应用于 `local_read_file / local_write_file / local_list_files` 的全部路径参数

## 命令白名单（command_policy.py）

- 只允许 `allowed_commands` 内的**命令名**（去扩展名、小写比对）
- `shlex.split(posix=False)` 拆分 + `subprocess.run(shell=False)`，杜绝 shell 注入
- **引号处理**：Windows 下 posix=False 拆分会保留引号字符（如 `python -c "code"` 拆出 `'"code"'`），会把代码当字符串字面量静默执行、零输出。拆分后统一剥掉参数首尾成对引号（`_unquote`），`-c` 才能真实执行；带空格的路径参数由 subprocess 自行加回引号

## 参数级路径校验（exec_tool.py）

命令白名单只校验命令名，`python -c "shutil.copy2('x', r'E:\...')"` 这类命令可携带任意绝对路径参数**绕过目录白名单**。因此对命令参数中的绝对路径做二次校验：

- **覆盖范围**：
  - 普通参数（如 `python E:\tmp\a.py` 中的脚本路径）
  - path-flag 的值（`--python` / `-o` / `--config` / `--cwd` / `-C` 等）
  - `python -c` / `node -e` 代码块内**字符串内嵌的路径**（含 `r'...'` 原始字符串、单双引号）
- **规则**：解析出的每个绝对路径必须落在 `allowed_dirs` 内，否则抛 `PermissionError`，返回「拒绝访问：命令参数中的路径 …超出允许目录范围」
- 注意：解析基于正则匹配字符串内的盘符路径（`X:\...`、UNC `\\...`），不执行代码、无副作用

## 可执行文件解析（exec_tool.py）

Windows 下 `subprocess.run`（底层 `CreateProcess`）查找可执行文件使用**父进程 cwd + PATH**，而非子进程 `cwd` 参数——相对路径（如 `.venv\Scripts\python.exe`）会被解析到**服务启动目录**，导致跑错解释器（装/用错 venv）。修复：`argv[0]` 为相对路径且 `workdir/argv[0]` 存在时，绝对化到 workdir 再执行。

## 超时与资源（exec_tool.py / server.py）

- 单次命令执行超时：`exec_timeout_seconds`（建议 120s，装依赖可能耗时）
- 文件读取大小上限：`max_file_size_bytes`（默认 1 MiB）
- 命令执行结果聚合返回 `exit_code / cwd / stdout / stderr`，错误兜底为中文错误文本，不抛异常冒泡

## 审计日志（audit.py）

- 每次调用记录：`时间 [INFO] tool=<工具> success=<成功与否> duration_ms=<耗时> <参数摘要> [message=<错误>]`
- **脱敏**：参数值统一转字符串并截断到 200 字符（`_redact`），换行折叠，避免文件全文/大段内容落盘；`local_write_file` 只记 `content_len`
- 滚动落盘：`max_bytes` / `backup_count`，UTF-8 编码

## 已知边界（如需加固可扩展）

- 命令参数解析基于正则，极端混淆（如编码绕过）可能漏判——白名单命令本身有限，风险可控
- 审计脱敏是长度截断而非关键词替换，超长敏感参数可能部分落盘；如需要可加关键词替换
- stdio 模式（如有）无 DNS-rebinding 防护，仅建议 http 模式
