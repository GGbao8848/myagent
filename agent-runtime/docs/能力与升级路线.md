## 当前能力（已实现，实测验证）

### 工具能力

| 工具 | 能力 | 实测 |
|---|---|---|
| `local_exec` | 执行白名单命令，返回 exit_code / stdout / stderr | ✅ 引号修复后 `-c` 真实执行；相对 exe 绝对化到 workdir |
| `local_read_file` | 读取白名单目录内文本文件（≤1 MiB） | ✅ |
| `local_write_file` | 覆盖写入白名单目录内文件 | ✅ |
| `local_list_files` | 列出白名单目录内文件/子目录（类型/大小/修改时间） | ✅ |

### 安全能力（四层防护，全服务端强制）

1. **只监听 localhost** + MCP DNS-rebinding 防护
2. **目录白名单**：realpath 归一化，`..`/符号链接/UNC 逃逸拦截
3. **命令白名单**：命令名比对（去扩展名）+ `shell=False` 杜绝注入；参数首尾引号剥离保证 `-c` 真实执行
4. **参数级路径校验**：命令参数（含 `python -c`/`node -e` 代码内嵌、path-flag 值）中的绝对路径必须落在白名单目录内
5. **审计日志**：每次调用落盘（工具/参数摘要/耗时/结果），敏感内容截断脱敏，滚动存储

### 执行环境（实测 12/12 测试用例通过）

- workspace 专属 venv（Python 3.11.15），预装常用库：`matplotlib 3.11.1` `numpy 2.4.6` `pandas 3.0.5` `openpyxl 3.1.5` `requests 2.34.2` `pillow 12.3.0` `seaborn 0.13.2`
- 缺库自动装：`uv pip install --python .venv\Scripts\python.exe <包>`（uv 已入白名单）
- 单命令超时 120s；命令白名单：`python node npm git pip uv dir ls echo type where mkdir`

### 集成能力（与 BR-Agent）

- BR-Agent 桌面客户端本机操作统一经服务器代理到 `mcp_local_*`（有白名单 + 审计，无裸本地工具）
- 服务器 MCP 连接缓存 **120s TTL + 连接失效自动重连**（MCP 重启后自愈，无需手动干预）
- agent ReAct 循环有护栏：单轮模型 2min / 整轮 5min，超时落库明确错误

## P0 稳定性与健壮性

### 1. 服务自启与守护（最重要）

- **现状**：开发环境手动启动（`Start-Process` 脱离会话）；`packaging/install_service.ps1` 提供 NSSM 装服务，未在开发机启用
- **升级动作**：生产机启用 NSSM 服务（开机自启 + 崩溃自动拉起）；`pyproject` 加 `[project.scripts]` 入口便于安装
- **收益**：MCP 服务无人值守，agent 随时可用

### 2. 连接健康探测

- **现状**：BR-Agent 靠「调用失败 → 识别连接错误 → 重建重试」，自愈但首击失败（MCP 刚重启后的第一次调用仍报错）
- **升级动作**：BR-Agent 加定时探测（如每 60s ping MCP 端点）或 `getMcpClient` 懒刷新校验 session 有效性；客户端侧显示「MCP 连接状态」
- **收益**：MCP 重启对用户无感，首击即成功

### 3. 优雅关闭

- **现状**：`taskkill /F` 强杀，streamable-http session 残留
- **升级动作**：`__main__.py` 捕获 SIGTERM/SIGINT，关闭 MCP server 与审计 handler（flush 日志）
- **收益**：日志完整、无端口假占

## P1 功能增强

### 1. 新工具（受控能力扩展）

| 工具 | 能力 | 安全约束 |
|---|---|---|
| `local_rm` | 删除文件/目录（进回收站或二次确认） | 目录白名单 + 危险命令需显式授权 |
| `local_zip` / `local_unzip` | 打包/解压工作区文件 | 目录白名单 |
| `local_process` | 列出/结束本机进程（按白名单过滤） | 仅查询默认放行，结束需授权 |
| `local_upload` / `local_download` | 与 BR-Agent 服务器/网盘互通文件 | 目录白名单 + 服务器鉴权 |

- **现状**：只有 4 个 local_* 工具，删除/压缩等能力缺失（agent 想删文件只能被告知不支持）
- **升级动作**：在 `tools/` 下新增实现 + 注册进 `server.py` + 配置开关
- **收益**：闭环能力更完整（清理临时文件、导出结果等），agent 不用拼命令绕过

### 2. 自动装依赖工具

- **现状**：agent 靠 `uv pip install --python ...` 命令装包（可用但需 agent 拼对命令）
- **升级动作**：新增 `local_install_pkg(packages)` 专用工具（内部固定 venv 路径、返回装包结果），避免 agent 拼错 `--python` 或误装系统环境
- **收益**：装包一步到位，路径错误类问题归零

### 3. 多 workspace 隔离

- **现状**：单 `allowed_dirs`，所有用户共享 `workspace`
- **升级动作**：按用户/项目拆分目录（`workspace/<user>/`），`local_*` 工具按登录用户路由
- **收益**：多人/多项目文件隔离，审计可归因

### 4. 超时分级

- **现状**：统一 120s
- **升级动作**：安装类命令（uv/pip）120s，普通命令 30s，脚本执行按参数指定
- **收益**：快速失败（脚本卡住不必等 2 分钟），慢操作不被误杀

## P2 安全加固

### 1. 敏感命令审批

- **现状**：白名单内命令直接执行；BR-Agent 客户端已有 `ToolConfirmDialog`（dangerous 工具需确认），但 MCP 侧无审批
- **升级动作**：MCP 增加「需审批命令」清单（如 `rm`/`format` 或带 `--delete` 参数的命令），执行前回调 BR-Agent 弹出确认；审计记录「审批人/结果」
- **收益**：破坏性操作有人工闸门，符合企业安全合规

### 2. 审计脱敏增强

- **现状**：长度截断（200 字符）+ 换行折叠
- **升级动作**：关键词替换（密码/密钥/token 正则掩码），可选 JSON-lines 结构化审计
- **收益**：敏感信息零落盘，日志可机器解析

### 3. 命令解析加固

- **现状**：参数路径用正则提取，极端混淆可能漏判（白名单命令少，风险可控）
- **升级动作**：对 `-c` 代码做 AST 级路径提取（Python 用 `ast` 解析）；对命令做字符级白名单（禁 `%`、`!`、反引号等）
- **收益**：越权通道进一步收窄

### 4. 文件类型白名单

- **现状**：目录内任意文件可读写
- **升级动作**：可配置允许的扩展名（如 `.py .json .csv .txt .png`），`local_read_file/write_file` 按扩展名过滤
- **收益**：降低读取敏感类型文件（`.pem/.env/.exe`）的风险

## P3 可观测性与运维

### 1. 结构化审计 / 指标

- **现状**：文本行日志，人工 `tail` 排查
- **升级动作**：审计改为 JSON-lines（`{"ts","tool","success","duration_ms","params"}`）；可选 Prometheus 指标（调用量/失败率/耗时分布）
- **收益**：可接入监控告警，性能问题可量化

### 2. BR-Agent 管理页连接状态

- **现状**：MCP 配置页只能手动「测试连接」
- **升级动作**：管理页显示 agent-runtime 实时状态（在线/离线/最近调用），连接失败直接给出重启指引（关联部署文档）
- **收益**：运维排障可视化，减少翻日志

### 3. 诊断信息包

- **升级动作**：一键收集（版本、config 摘要、最近审计、端口状态）打包下载
- **收益**：远程排障不再逐个文件拷

## P4 生态与分发

### 1. 多客户端接入

- **现状**：BR-Agent 走 `mcp_local_*` 代理；Claude/Cursor 等可直接填 `http://localhost:18544/mcp`（README 已说明）
- **升级动作**：README/文档补各客户端接入示例与权限建议（不同 agent 给不同白名单）
- **收益**：agent-runtime 成为通用本机能力底座，不止服务 BR-Agent

### 2. CI 打包与版本管理

- **现状**：`build.ps1` 手动打包；无版本号管理
- **升级动作**：GitHub Actions 触发打包（win x64），产物带版本号（`pyproject` version），changelog 维护
- **收益**：分发可追溯、升级回滚容易

### 3. 配置热更新

- **现状**：改 `config.yaml` 需重启
- **升级动作**：监听配置文件变更自动重载（白名单/超时），审计保留
- **收益**：策略调整零中断

## 代码升级流程（开发环境）

> 注意：**本地开发目录 `E:\br\MCP\agent-runtime` 与仓库副本 `E:\br\BR-Agent\agent-runtime` 是两份**。仓库副本是 BR-Agent 仓库的子目录（已推送），本地开发目录是正在运行服务的目录。升级步骤：

```bash
# 1. 从仓库拉取最新代码
cd E:\br\BR-Agent && git pull

# 2. 同步代码到本地开发目录（保留本地 config.yaml / workspace / venv，不覆盖）
robocopy E:\br\BR-Agent\agent-runtime E:\br\MCP\agent-runtime /E /XD .venv workspace /XF config.yaml *.log
# 或手动只复制改动的文件（src/、packaging/、config.example.yaml、pyproject.toml）

# 3. 重启服务（加载新代码）
#    找 PID：netstat -ano | findstr 18544 → taskkill /PID <pid> /F
#    重新 Start-Process 启动（见 docs/部署与运维.md）

# 4. 验证（可选）
curl -X POST http://127.0.0.1:18544/mcp ...   # initialize 握手
```

> 建议后续把开发目录切换到仓库内副本（或让 BR-Agent 直接读仓库副本），避免双份维护；见 P4「配置热更新/分发」升级项。
