# AgentRuntime 配置说明

> 配置文件查找顺序：环境变量 `AGENTRUNTIME_CONFIG` 指定路径 → 工作目录 `config.yaml` → `%PROGRAMDATA%\AgentRuntime\config.yaml`（安装后）。找不到时使用内置默认值（仅监听 localhost、**无任何授权目录与命令**，需显式配置后才能执行实际操作）。

## config.yaml 全项详解

```yaml
server:
  host: 127.0.0.1      # MCP 服务监听地址（强烈建议保持 127.0.0.1，防止局域网其他机器访问）
  port: 18544          # MCP 服务监听端口
  path: /mcp           # MCP 端点路径

security:
  # Agent 可访问的本地目录白名单（绝对路径）
  # 文件读写/列目录只能在这些目录内进行，超出范围会被拒绝（realpath 解析后校验）
  allowed_dirs:
    - E:\br\MCP\agent-runtime\workspace

  # 允许执行的命令白名单（仅命令名，不含参数；参数中的绝对路径另由参数级校验拦截）
  allowed_commands:
    - python
    - node
    - npm
    - git
    - pip
    - uv
    - dir
    - ls
    - echo
    - type
    - where
    - mkdir

  # 单次命令执行超时（秒）。安装大依赖（pip/uv）可能耗时较长，建议 ≥120
  exec_timeout_seconds: 120
  # 单次读取文件的最大字节数
  max_file_size_bytes: 1048576

logging:
  log_dir: ./logs          # 审计日志目录（安装后建议指向 C:\ProgramData\AgentRuntime\logs）
  audit_file: audit.log    # 审计日志文件名
  max_bytes: 10485760      # 单个日志文件最大字节数（超过则滚动）
  backup_count: 5          # 保留的滚动日志文件数
```

## 白名单变更说明

| 项 | 说明 |
|---|---|
| `uv` | 本会话新增：工作区 Python 由 uv 托管（externally-managed），装依赖必须走 `uv pip install`，故加入白名单 |
| `exec_timeout_seconds` | 30 → 120：`pip/uv install` 冷启动可达十几秒，30s 会被杀掉导致装包失败 |
| 删除 `python3/copy/move/rmdir` | 与模板的差异；`copy/move/rmdir` 属破坏性命令，按部署策略收紧 |

## Python 环境约定（写入 local_exec 工具描述，agent 会读到）

1. **执行脚本用工作区 venv 解释器**：`.venv\Scripts\python.exe`（相对 cwd），已预装 `matplotlib / numpy / pandas / openpyxl / requests / pillow / seaborn` 等常用库
2. **缺库用 uv 装到 venv**：`uv pip install --python .venv\Scripts\python.exe <包名>`，装完重试脚本
3. **禁止**系统 `python -m pip install`：uv 托管环境会报 `externally-managed-environment`
4. **禁止** `uv run` 执行脚本：无项目文件时自动下载 pyinstaller 创建临时环境，污染本机

> 背景：workspace 的 `python`（PATH 首位）实际是 uv 托管的 Python 3.11（`.venv` 由 `uv venv` 创建），系统 python 未安装（Windows Store 占位）。这也是「为什么不用裸 `python` 执行」的原因。

## 常见坑

- **相对可执行文件解析**：`subprocess` 在 Windows 用父进程 cwd + PATH 找可执行文件，`.venv\Scripts\python.exe` 这类相对路径会被解析到服务启动目录而非工作区——已由 `exec_tool.py` 自动绝对化到 workdir（详见安全设计文档）。
- **引号保留**：命令拆分后参数首尾引号会被剥离，`python -c "code"` 才能真实执行（详见安全设计文档）。
